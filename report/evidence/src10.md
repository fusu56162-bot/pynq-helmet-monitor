## 选定边界与拓扑

```text
原始输入 in0（3×224×224）
  → Reorg（12×112×112）
  → Conv0 INT8卷积（16×112×112 INT32累加）
  → 反量化 + bias + 原SiLU + Conv1输入量化
  → Conv1 INT8卷积，stride=2（32×56×56 INT32累加）
  → 反量化 + bias + 原SiLU
  → blob 4（32×56×56 float32）
  → 原有split，分别进入conv_2与conv_5，其余模型暂留ARM
```

这五层之间没有外部旁路消费者，边界位于第一个Split之前，适合先构建一段连续硬件子图。
不得只加速Conv0后仍把中间SiLU/再量化交给ARM，却宣称完成了上述硬件连续计算。
可以分阶段验证子模块，但每一步必须明确尚未硬件化的部分，完整子图验收前不改变部署。

## 中间SiLU/再量化：先研究精确离散映射

前一卷积输出是有限INT32整数，下一卷积只消费INT8。
因此尝试以每个输出通道的完整整数映射，合并原有反量化、bias、SiLU和再量化：
`q1 = original_ARM_quantize(original_ARM_SiLU(original_ARM_dequantize(sum0)))`。
这不是把SiLU换ReLU，也不是用插值拟合代替现有函数。

必须由实际板卡同版本ncnn原算子生成映射，并且与完整模型提取的中间数据逐项核对。
不能拿NumPy exp、PC ncnn或不同舍入规则生成的表冒充ARM一致。
必须核对packed布局、32位乘加次序、负数取整、饱和及非单调负半区。

模型第一层输入量化值在[0,127]时，16通道保守完整INT32域合计1,488,710个整数。
每通道范围可由127×负权重之和/正权重之和严格包围，包含padding=0产生的值。
这是穷举真值表生成的规模，不是需要存入FPGA的最终ROM规模。

当前`reference_capture/codec.py`把完整真值表无损压缩为分桶数据，每桶至多一个转折，支持正负方向和任意INT8跳变，并无损裁去常数尾段。
`reference_capture/lut_core.cpp`使用7字段配置，只做整数地址/位操作和比较，不直接计算浮点exp。不要使用旧`activation_lut`目录下的5字段版本解码当前数据。
原始ROM预算暂定64KiB；超预算就停止改架构，不能偷偷近似。最终BRAM/DSP/时序须综合和实现验证。
实际ARM已对全保守域生成映射并核对原算子；PC复核与HLS解码器穷举也已通过。这仍不代表新硬件上板、整网速度或数据集精度验收通过。

最后一个SiLU输出是float32，不能直接套用上面的INT8输出表；需要单独设计并验证，禁止假装已解决。

## 数据和资源

- 倾向片上行缓存和FIFO衔接，不经ARM回传中间层。必要时的PL直访DDR也必须计带宽与时间。
- 首层INT8中间整图200704字节，末端float32整图401408字节。优先流式/分块组织，不能把全部数组同时塞BRAM而不算容量。
- 两核流水可先评估约96+96=192个卷积乘法DSP的结构；16输入通道按6并行须处理尾组，不得越界或丢通道。
- 192只是候选卷积乘法预算，不是综合结果，更不含全部其它功能。总DSP上限220，还要看LUT/BRAM/时序及预处理原模块。
- 可对比共享计算阵列、PL内部多阶段复用的结构，但不得在ARM里循环调用两个独立单层接口冒充内部流水。
- 保留当前float32输入的公平计时口径。若改成byte输入，必须证明归一化/首层量化完全一致，并分别记录模型API变化及离线端到端耗时。
- 全部ARM边界转换、DMA、缓存同步、输出布局转换均计入替换路径；不能把每帧开销挪到setup。
- 输出需与ncnn packed4布局/内存所有权正确衔接，保留两个后续分支。裸HWC32字节流不能直接冒充ncnn packed4。
