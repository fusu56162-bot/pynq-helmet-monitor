# PYNQ 板卡准备与排障

先辨明用户在操作板卡 Linux、电脑终端还是云 GPU。它们的文件系统、Python、供电与关机对象不同。沿用户现有连接工作，不把某次工程的 IP、端口、路径当作 PYNQ 默认值。

## 低影响诊断

- 先读报错、工程入口与已有日志；简单操作问题不用启动整套测试。
- 需环境信息时使用本技能 `scripts/inspect_board.py`。只读取系统文件和磁盘容量，不导入 PYNQ 驱动、打开相机、访问 MMIO、分配 CMA 或加载位流。默认打印 JSON；仅显式 `--output` 新建报告。
- 电脑上运行得到电脑信息。保留主机身份和 `hardware_test_performed=false`，不能当作板卡自检通过。
- 板卡不开机、连接重置、Jupyter 服务停止、Notebook 内核异常分层处理：电源/启动 → 链路/IP → 服务/端口 → 内核/程序。
- 供电和启动介质分开描述。PYNQ-Z2 可以是“USB 供电、SD 卡启动”；其他板型、跳线编号与电压查对应手册。

## 存储、备份与进程

- 查询目标文件系统的可用字节；目录大小不等于剩余容量。先定位大文件，不因空间检查删除文件。
- 小核验 ZIP、清单、截图不等于完整回退备份。完整归档应有清单、哈希和可读性检查；未完成的浏览器临时下载文件不要改名冒充成功。
- 清单保护的文档被删后，从原发布包按原字节恢复。不要绕过整份校验，或重算清单掩盖原文件缺失。
- 先确认谁持有相机、DMA、锁与缓冲区，正常停止所属程序。删锁文件、批量杀 Python 或强制换位流不能处理未知所有权。
- 库存 base overlay 某 DMA 未 Halt 不等于加速器损坏；先核对实际 IP/驱动和状态。

命令与故障分层见 [references/board-operations.md](references/board-operations.md)，仅在需要时读取。

## 交付

给能在用户当前界面直接执行的步骤，写清终端对象、目录、结束标志和返回文件。用户选择手动运行时，不代为启动相机或编程 PL；既有授权已覆盖必要操作时不重复确认。

正常关机先结束程序并保存结果，再执行板卡操作系统关机命令；网页断连后留停机时间再断电，不用 RST 代替关机。

文件校验、主机模拟与真实板卡测试分别记录，不将任一阶段状态冒充整机通过。
