# 01 四类224输入与功能边界冻结

**形式：** 提示词工作流＋契约模板。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

接入模型、改预处理或写报告前，固定本项目四类检测及PS/PL分工。

## 所需输入

- 现行Notebook入口与模型param/bin
- 预处理和解码源码
- 当前位流及HWH身份

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-project-contract`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 从实际入口追到输入张量，逐项核对RGB/BGR、最近邻缩放、padding、CHW和归一化。
2. 确认3087×9输出已经解码，保持ebike/rider/helmet_head/bare_head顺序和分类NMS。
3. 把当前实现、计划候选、已取消功能分列；不得把不存在的越线、信号灯或乘客关联写回交付。
4. 改模型或预处理后生成新契约版本，与旧版逐项比较，不覆盖原记录。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/verify_release.py --root .
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 版本化输入输出契约
- PS/PL职责与功能边界表
- 变更影响和必要补测清单

## 失效条件与停止边界

- 只有ONNX文件，没有预处理/类别顺序时不能认定可直接接入。
- 输出已解码时再做sigmoid或重复坐标缩放会破坏结果。
- 本契约仅适用当前224四类发布版，迁移其他题目需重新填写。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。
