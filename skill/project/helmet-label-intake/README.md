# 03 四类标注接收与空场甄别

**形式：** 校验脚本＋数据接收模板。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

接收Make Sense/YOLO标签，检查中文类别映射、缺标签和真实空场。

## 所需输入

- images与labels目录
- 导出类别文件/明确ID顺序
- 人工确认空场名单和按片段分组信息

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-label-intake`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 先查类别ID映射，中文名称可以映射但不能凭显示名称推断数字顺序。
2. 每张可见目标完整标ebike、rider、对应helmet_head或bare_head；只标头部的旧数据另列partial。
3. 缺失txt标为待处理，不自动当空场；有确认名单才给缺失图空场身份。
4. 检查每行5字段、类ID、归一化范围、宽高和越界；相邻视频帧按片段分组防止泄漏。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/audit_yolo_labels.py --images 数据/images --labels 数据/labels
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 标签格式与覆盖报告
- 已确认空场/未标注/部分标注列表
- 可训练与独立评估划分建议

## 失效条件与停止边界

- 无classes映射时无法确定类别语义。
- 有目标却缺标签会产生错误负样本。
- 同一骑行片段相邻帧分到训练和测试会高估泛化。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。
