# 23 B/C协作任务与候选交付验收

**形式：** 完整提示词模板＋验收矩阵。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

把硬件/调度/摄像头任务分给协作者，同时保持当前发布入口和公共接口稳定。

## 所需输入

- 任务版本与明确职责
- 最小源码、模型身份、参考数组和接口
- 禁止覆盖内容与阶段性验收条件

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-team-handoff`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 先写具体瓶颈与交付边界，例如owned pack4完整层而非整数tile裸核。
2. 提示词同时给输入材料路径、正确性规则、可改范围、报告口径和必交文件；不能只发一句优化。
3. 接收时先查任务版本/公共类型/所有权/源哈希，再host、ARM、上板分级验收。
4. 给出通过/未验/失败及下一步，候选不整包覆盖主工程；不未经用户授权发送消息给协作者。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/verify_manifest.py --root . --manifest manifest.json
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 可直接转发的任务提示词
- 输入材料与哈希清单
- 分阶段验收矩阵和反馈

## 失效条件与停止边界

- 第一版任务实现不能冒充修订任务验收。
- host36/66组通过不等于ARM浮点或FPGA速度通过。
- 不同成员公共接口版本冲突时不能互相覆盖。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。
