# 02 发布包身份、完整备份与回退

**形式：** 校验脚本＋踩坑清单。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

整理交付、恢复误删文件、检查完整备份及候选版本隔离。

## 所需输入

- 原发布包与SHA256清单
- 待核验目录或结果ZIP
- 电脑上完整备份的位置与校验记录

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-release-rollback`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 区分完整traffic_project归档、MANIFEST和小结果ZIP，记录各自覆盖范围。
2. 先用verify_manifest检查原文件，缺失文档从原包按字节恢复，不重算原清单掩盖差异。
3. 浏览器临时下载后缀仍在时不视为完整归档；核对大小、可读性及哈希。
4. 候选另建目录，回退引用已核验的模型/bit/HWH组合；只读检查不删除SD内容。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/verify_manifest.py --root . --manifest manifest.json
```

```bash
python skill/_shared/tools/verify_release.py --root .
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 文件身份报告
- 备份覆盖范围表
- 明确的恢复对象和回退入口

## 失效条件与停止边界

- 只有核验ZIP不能恢复完整工程。
- 模型、位流或HWH任一不匹配时不能宣称恢复发布版。
- 重写哈希会毁掉原发布身份；应另立新版本。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。
