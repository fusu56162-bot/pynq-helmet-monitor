# 26 源码归档、许可证与技能包复现

**形式：** 工程骨架＋清单校验脚本。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

交付可复现的当前检测源码与skill目录，保留原发布身份并隔离候选。

## 所需输入

- 原源码清单与来源表
- 模型/bit/HWH与运行依赖说明
- 第三方许可证及技能目录

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-source-reproducibility`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 分区放已验证运行、PL源码、训练转换、验证与许可证，现有受保护发布文件按字节保留。
2. 不携带云凭据、大训练图和无关业务模块；遗留HWH元数据如实说明，不伪造删改。
3. 每个技能有适用范围/使用方法/失效条件/验证证据/经验来源，通用与项目技能分区。
4. 生成路径受限SHA256清单、ZIP CRC及复现检查；按当前仓库清单核对受保护文件，1034项仅指历史源码包。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/verify_manifest.py --root . --manifest manifest.json
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 可提交源码目录和ZIP
- 技能目录/README/验收记录
- 原文件未变与包完整性报告

## 失效条件与停止边界

- 源码包不是通用SD镜像，ncnn ARM依赖仍需按说明准备。
- 将未验证候选设成默认入口会破坏已验证路线。
- 只有目录/提示词没有使用和失效条件不满足复用要求。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。

- [source_package](../../_shared/evidence/source_package.json)
- [release_identity](../../_shared/evidence/release_identity.json)

**本次技能包检查：** 见[离线验证记录](../../validation.json)。包括可发现结构、内部引用、模板完整性，以及适用工具的真实归档/故障fixture检查。本次未重开相机、未加载位流、未新训练；尚未进行陌生队伍跨题目迁移验收。

## 从哪些失败或观察中提炼

来自清理越线逻辑、保留原硬件身份、只对检测结构重建与提交包离线核验。

## 迁移到其他工程

保留判断方法，替换本项目契约和黄金参考；如果形状、算子语义、数据来源、并发结构或硬件接口变化，原数值/性能结论不可直接沿用。通用PYNQ方法另列于[general/](../../general/)，不是把项目固定常量推广成通用要求。
