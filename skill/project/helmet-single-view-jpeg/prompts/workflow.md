# 可直接使用的任务提示词：单画面JPEG一次编码与板端画质A/B

请结合当前四类224输入、178-DSP前段加ARM续算项目，完成以下任务：
在保持推理输入不变时比较出板JPEG质量、宽度、字节及显示开销。

我提供的材料位置（按实际填写，不存在就标缺失）：
- 单画面入口quality_camera.py
- 质量/宽度参数与同帧图片
- JPEG编码、缩放、提交及forward计时

先读取本目录README.md以及../../_shared/project_profile.json。用户当前约束覆盖历史默认配置；不擅自恢复已取消功能，不以历史测量填充本次结果。

执行与判断：
1. 保留固定224推理输入，只调整显示输出参数；缩小网页CSS不改变上传字节。
2. 同帧JPEG编码一次供显示和保存共享，分别记录编码与Jupyter提交。
3. 先比较Q80/Q60原宽，再独立比较缩放，记录字节和CPU成本；顺序现场单轮不做稳定因果结论。
4. 原MJPG已经模糊时检查调焦/曝光，不把训练或显示Q80当源头。

输出：
- 画质-字节-耗时对照表
- 固定推理输入证明
- 最终展示参数及局限

在结尾单独说明：更小图像可能因ARM缩放额外耗时而更慢。; Jupyter提交完成不是浏览器呈现完成。; 同帧图与不同时间姿态不能直接做压缩画质对照。
区分历史验证、本次离线检查、仍需板端实测。不要把数值一致、识别精度和速度收益混为同一个通过标志。
