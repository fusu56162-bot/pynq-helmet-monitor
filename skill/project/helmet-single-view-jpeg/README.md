# 18 单画面JPEG一次编码与板端画质A/B

**形式：** 已验证案例＋参数实验模板。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

在保持推理输入不变时比较出板JPEG质量、宽度、字节及显示开销。

## 所需输入

- 单画面入口quality_camera.py
- 质量/宽度参数与同帧图片
- JPEG编码、缩放、提交及forward计时

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-single-view-jpeg`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 保留固定224推理输入，只调整显示输出参数；缩小网页CSS不改变上传字节。
2. 同帧JPEG编码一次供显示和保存共享，分别记录编码与Jupyter提交。
3. 先比较Q80/Q60原宽，再独立比较缩放，记录字节和CPU成本；顺序现场单轮不做稳定因果结论。
4. 原MJPG已经模糊时检查调焦/曝光，不把训练或显示Q80当源头。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/summarize_run.py skill/_shared/fixtures/camera_result_excerpt.json
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 画质-字节-耗时对照表
- 固定推理输入证明
- 最终展示参数及局限

## 失效条件与停止边界

- 更小图像可能因ARM缩放额外耗时而更慢。
- Jupyter提交完成不是浏览器呈现完成。
- 同帧图与不同时间姿态不能直接做压缩画质对照。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。

## 已验证的效果

**历史项目证据：** Q60字节约减48.6%，整机FPS仅单轮小幅变化；缩至480新增约47ms缩放且未更快。
