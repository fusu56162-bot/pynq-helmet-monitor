# 可直接使用的任务提示词：双预览竞争退化的定位与回退

请结合当前四类224输入、178-DSP前段加ARM续算项目，完成以下任务：
解释原始预览与识别分离后ARM续算变慢，避免将双线程等同自动提速。

我提供的材料位置（按实际填写，不存在就标缺失）：
- 原单画面与双画面同口径结果
- ARM线程/解码/JPEG开销
- 图像ID与CPU占用/频率信息

先读取本目录README.md以及../../_shared/project_profile.json。用户当前约束覆盖历史默认配置；不擅自恢复已取消功能，不以历史测量填充本次结果。

执行与判断：
1. 核对模型/硬件是否未变，先查新增预览线程做了哪些解码、缩放、编码和提交。
2. 比较完整forward与嵌套ARM段，区分计算退化与相机启动失败。
3. 在可比场景下只关预览做A/B；没有频率/带宽证据时只列竞争解释为推断。
4. 若端到端更新率退化，恢复单画面入口；不把快预览标成快识别，也不把旧框贴新帧冒充同帧。

输出：
- 新增负载清单
- 同口径回归对照
- 回退方案与未确认原因

在结尾单独说明：原始预览5FPS与识别1FPS不是同一指标。; 只看CPU百分比不能确定DDR或降频是根因。; 异步旧框需要年龄/ID标识，不能隐去。
区分历史验证、本次离线检查、仍需板端实测。不要把数值一致、识别精度和速度收益混为同一个通过标志。
