# PYNQ Overlay 与 DMA 接入

## 当前设计身份

查当前工程的板型、器件、PYNQ 版本、`.bit/.hwh` 对与哈希、IP 名称/类型/地址、PL 时钟、驱动和缓冲格式。地址与时钟来自该设计，不套用历史常量。

磁盘 HWH、PYNQ 缓存/解析的 IP 字典、实际编程的 PL 是三件事。不一致时先查加载和元数据生命周期，不改硬件地址迎合旧检查。

`Overlay(path)` 默认下载位流；仅解析时明确使用当前版本支持的 `download=False`。不能凭 `.reset()` 名称将其当作硬件 DMA 停机证据。

## 传输前核对

- 确认硬件拥有者和退出路径；只要求审查时完成本地审查及可复现包，不启动板卡测试。
- 核对 AXI DMA、VDMA 或其他核，单/双向、simple/SG、数据位宽和长度单位。不用同一寄存器表猜测全部 IP。
- 明确连续缓冲区的设备地址、dtype、形状、布局、对齐、有效元素、padding 和边界区。NumPy 虚拟地址不能代替设备地址。
- 非一致性缓存：PS→PL 启动前同步到设备，PL→PS 完成后同步回主机。以缓冲区属性及驱动为准。
- 输出端先就绪通常有助于避免回压死锁，具体启动顺序仍取决于 IP 协议，沿用工程已验证顺序。

## 完成与清理

“启动过”“传完”“计算完成”“输出有效”“数值正确”分别证明。等待有超时，失败保留控制/状态、长度与原异常。

只有相关 DMA/IP 已确认停止且不再访问缓冲区，才能释放 CMA 或换位流。超时后硬件状态未知时保留拥有者和诊断，使用已验证恢复路径，不在 `finally` 无条件 free。

已知核才执行专属 stop/reset 并验证；不能确认安全停止时不叠加新实验。旧 overlay 恢复为单独阶段，未尝试/成功/失败分别记录，恢复失败不能整轮标 PASS。

详见 [references/dma-lifecycle.md](references/dma-lifecycle.md)。

## 交付

提供成对硬件文件及哈希、接口说明、单轮运行入口、停止/恢复路径和原始数值。只改驱动/校验不等于硬件计算优化；HLS 综合、Vivado 实现、真实上板分别报告。
