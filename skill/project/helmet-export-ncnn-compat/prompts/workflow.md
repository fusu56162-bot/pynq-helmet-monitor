# 可直接使用的任务提示词：ONNX/ncnn导出与算子兼容

请结合当前四类224输入、178-DSP前段加ARM续算项目，完成以下任务：
固定224导出候选并处理当前ARM ncnn不支持的图算子。

我提供的材料位置（按实际填写，不存在就标缺失）：
- 模型与导出代码版本
- MODEL_INTERFACE和转换日志
- ARM实际ncnn版本/编译选项及失败节点

先读取本目录README.md以及../../_shared/project_profile.json。用户当前约束覆盖历史默认配置；不擅自恢复已取消功能，不以历史测量填充本次结果。

执行与判断：
1. 分别保留PyTorch、TorchScript/ONNX和ncnn模型身份与固定形状。
2. 先逐节点定位不支持算子，如CopyTo，核对复制/别名/生命周期语义，不批量删节点。
3. 对兼容前后跑同一输入raw输出，再比较边界张量和检测框。
4. 生成独立兼容补丁包，标出它不等于量化、FPGA接入或精度验收。

输出：
- 导出接口与算子差异表
- 最小兼容修复及回放对照
- 转换日志与文件哈希

在结尾单独说明：能加载模型不代表输出语义未变。; 转换器版本不同可能引入新算子。; 改变输入形状不能仅修改ONNX入口标注。
区分历史验证、本次离线检查、仍需板端实测。不要把数值一致、识别精度和速度收益混为同一个通过标志。
