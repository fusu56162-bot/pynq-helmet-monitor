# 可直接使用的任务提示词：有界后台存证与同帧追溯

请结合当前四类224输入、178-DSP前段加ARM续算项目，完成以下任务：
在保留原始帧、输入、raw输出、框和图像的同时控制存储对主循环影响。

我提供的材料位置（按实际填写，不存在就标缺失）：
- 保存用途与频率要求
- writer队列及缓冲所有权
- RESULT.json与同帧文件组织

先读取本目录README.md以及../../_shared/project_profile.json。用户当前约束覆盖历史默认配置；不擅自恢复已取消功能，不以历史测量填充本次结果。

执行与判断：
1. 明确抽样存证和完整录像的区别，不擅自删除用户要保留的证据支路。
2. 约每秒一组只是当前策略；有界队列最多2组，满队列记丢弃，不阻塞实时取帧。
3. 入队对象为不可变快照，不能持有马上被采集/DMA复用的数组。
4. 停止先终止生产、按约定排空/丢弃并确认worker退出，再释放；缺文件与保存失败保留状态。

输出：
- 保存策略与队列所有权表
- 同帧证据文件清单
- 停止/排空/丢弃统计

在结尾单独说明：后台写耗时与主循环并行，不能重复相加推导FPS。; 同名frame编号跨session可能碰撞，必须带session身份。; join超时不等于线程已停，不能释放仍在用的内存。
区分历史验证、本次离线检查、仍需板端实测。不要把数值一致、识别精度和速度收益混为同一个通过标志。
