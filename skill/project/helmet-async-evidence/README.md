# 17 有界后台存证与同帧追溯

**形式：** 案例模板＋所有权检查清单。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

在保留原始帧、输入、raw输出、框和图像的同时控制存储对主循环影响。

## 所需输入

- 保存用途与频率要求
- writer队列及缓冲所有权
- RESULT.json与同帧文件组织

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-async-evidence`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 明确抽样存证和完整录像的区别，不擅自删除用户要保留的证据支路。
2. 约每秒一组只是当前策略；有界队列最多2组，满队列记丢弃，不阻塞实时取帧。
3. 入队对象为不可变快照，不能持有马上被采集/DMA复用的数组。
4. 停止先终止生产、按约定排空/丢弃并确认worker退出，再释放；缺文件与保存失败保留状态。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/verify_manifest.py --root . --manifest manifest.json
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 保存策略与队列所有权表
- 同帧证据文件清单
- 停止/排空/丢弃统计

## 失效条件与停止边界

- 后台写耗时与主循环并行，不能重复相加推导FPS。
- 同名frame编号跨session可能碰撞，必须带session身份。
- join超时不等于线程已停，不能释放仍在用的内存。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。
