# 04 固定224四类训练与轮次归档

**形式：** 提示词工作流＋实验计划模板。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

继续训练当前轻量模型，保持单次整图四类能力与可比验证，不接管云账户。

## 所需输入

- 固定训练脚本/YOLOv5版本
- 按场景划分的数据清单
- 上一轮best/last、日志和验证集范围

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-train224-rounds`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 保持224输入和四类顺序，先小规模smoke确认数据/验证/保存链能完成。
2. 记录初始化权重、seed、batch、workers、学习率、增强与early-stopping设置；训练轮数不等于独立实验轮次。
3. 需要训练满时明确禁用早停，同时保留best与last，不能把最后epoch当自动最佳。
4. 按相同验证集比较每类TP/FP/FN、P/R和mAP；训练后导出固定接口候选，不直接覆盖现场模型。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

## 交付物

- 可执行训练参数表
- 轮次及checkpoint身份表
- 每类验证结果与未达标项

## 失效条件与停止边界

- 在新镜像里混用旧虚拟环境可能重新拉错Torch。
- mAP或某个epoch最大值不能拼成同时满足所有目标的模型。
- 校园无戴盔正样本时无法证明校园戴盔精度。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。
