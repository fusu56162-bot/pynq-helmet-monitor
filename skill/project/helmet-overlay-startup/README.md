# 09 178-DSP发布图接入与启动故障定位

**形式：** 踩坑清单＋身份检查脚本。**定位：** 当前四类224输入头盔检测项目的经验包，不是新的板端实验结果。

## 适用范围

当前发布图加载前核对bit/HWH、IP、时钟、所有权和历史base元数据差异。

## 所需输入

- 当前模型/bit/HWH与清单
- PYNQ版本、实际ip_dict和当前运行拥有者
- 启动错误的原始阶段/寄存器记录

共享事实先读[项目契约](../../_shared/project_profile.json)。其中类别、阈值、地址、100MHz和178DSP仅适用当前发布版。

## 使用方法

让助手读取本目录SKILL.md，或在支持技能发现的环境调用 `$helmet-overlay-startup`；将材料位置填入[prompts/workflow.md](prompts/workflow.md)，按下面顺序执行。

1. 先核文件身份再加载，区分磁盘HWH、解析字典和当前PL，固定地址只对该发布图生效。
2. 检查辅助BRAM条目差异、合法MMIO范围和DMA类型，逐项修复已证实的旧假设。
3. 库存trace DMA未Halt时先定位拥有者，使用已验证的停止/复查流程，不删锁或盲复位。
4. 任何恢复失败独立记录，不将未尝试恢复写成已恢复178。

结果填入[assets/record-template.json](assets/record-template.json)。它是未执行模板，空值不代表通过。

可复验命令（从含skill/的目录执行）：

```bash
python skill/_shared/tools/verify_release.py --root .
```

`--root .`与manifest.json用于完整源码包；独立技能ZIP不含生产模型/位流，需提供匹配源码根目录。

## 交付物

- 发布身份报告
- 启动阶段与根因矩阵
- 受控加载/停止/恢复步骤

## 失效条件与停止边界

- Overlay(path)可能立即下载，不能用于假定只读的检查。
- 当前图与HWH不匹配时不能借旧地址写MMIO。
- 恢复失败或缓冲仍被访问时不能继续下一轮。

用户只要求分析或手动上板时，完成离线分析/可运行交付后给操作步骤，不自行触发真实设备实验。其他题目先替换模型、布局、时钟、地址和评估定义，再重新验证。

## 已验证的效果

**历史项目证据：** 后续V3返回记录确认trace DMA停止复查和匹配178恢复成功；生产身份另由发布与摄像头记录确认。

- [release_identity](../../_shared/evidence/release_identity.json)
- [v3](../../_shared/evidence/v3.json)

**本次技能包检查：** 见[离线验证记录](../../validation.json)。包括可发现结构、内部引用、模板完整性，以及适用工具的真实归档/故障fixture检查。本次未重开相机、未加载位流、未新训练；尚未进行陌生队伍跨题目迁移验收。

## 从哪些失败或观察中提炼

来自V3启动先后遇到锁占用、辅助BRAM条目、地址范围与库存trace DMA状态四类前置失败。
