# 可直接使用的任务提示词：178-DSP发布图接入与启动故障定位

请结合当前四类224输入、178-DSP前段加ARM续算项目，完成以下任务：
当前发布图加载前核对bit/HWH、IP、时钟、所有权和历史base元数据差异。

我提供的材料位置（按实际填写，不存在就标缺失）：
- 当前模型/bit/HWH与清单
- PYNQ版本、实际ip_dict和当前运行拥有者
- 启动错误的原始阶段/寄存器记录

先读取本目录README.md以及../../_shared/project_profile.json。用户当前约束覆盖历史默认配置；不擅自恢复已取消功能，不以历史测量填充本次结果。

执行与判断：
1. 先核文件身份再加载，区分磁盘HWH、解析字典和当前PL，固定地址只对该发布图生效。
2. 检查辅助BRAM条目差异、合法MMIO范围和DMA类型，逐项修复已证实的旧假设。
3. 库存trace DMA未Halt时先定位拥有者，使用已验证的停止/复查流程，不删锁或盲复位。
4. 任何恢复失败独立记录，不将未尝试恢复写成已恢复178。

输出：
- 发布身份报告
- 启动阶段与根因矩阵
- 受控加载/停止/恢复步骤

在结尾单独说明：Overlay(path)可能立即下载，不能用于假定只读的检查。; 当前图与HWH不匹配时不能借旧地址写MMIO。; 恢复失败或缓冲仍被访问时不能继续下一轮。
区分历史验证、本次离线检查、仍需板端实测。不要把数值一致、识别精度和速度收益混为同一个通过标志。
